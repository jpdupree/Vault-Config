📂 Load Real Vault Data

This dashboard ships with sample data. To document a real environment, load a configuration JSON file with 📂 Load Data (top right). It accepts three formats: a Vault .cfg Global Settings export (File ▸ Export in the Vault client), this dashboard's own exported JSON, and raw Vault API output. When you load a .cfg, an ⬇ Export .cfg button appears — it preserves that original package and patches your lifecycle edits back in so it re-imports into Vault. You can also generate JSON by running the included Export-VaultConfig.ps1 PowerShell script against your ADMS/Vault server, then load the resulting file here. Your data is kept only in this browser (💾 Save / ↺ Reset) — nothing is uploaded.

Tip: the Replace toggle (next to Load Data) controls how a file is applied — when on, any section missing from the file is cleared so only the file's data remains (a clean full replace); when off it merges, keeping current data for sections the file doesn't contain.

⬇ Export Vault .cfg — what this updates

Your edits are patched into the loaded Vault Global-Settings package. Everything not listed under "written" is preserved exactly as imported. Review before exporting:

✅ Written back to the .cfg
  • Lifecycles — states, colors, default, comments, transitions
  • Transition Actions / Criteria / Security
  • Revision schemes & sequences
  • Categories — lifecycle/revision assignment
  • Properties (UDP) — Active flag, new custom props
  • File Numbering scheme
  • Category Rules
  • Content-source Property Mappings
📄 NOT written (documentation only)
  • Users, Groups, Roles
  • Server/DB, Job Processor, Thin Client
  • Security policy (password, AD/LDAP)
  • CAD Integration page, Email, API, Backup, Audit
  • Fusion Manage connector (tenant, mappings, states)
  • Folder structure, General Settings, Notes
Less-obvious limits: Transition Custom Job Types & Peer Review are not written (no element in the export). Only File numbering is included (Item/Change-Order numbering live in Vault's base data); number prefixes/free-text fields aren't generated. Property mappings keep the exact moniker but not the friendly file-property name / classification. Roles & user accounts are server-level, never part of this .cfg.
