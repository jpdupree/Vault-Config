Vault Configuration Overview
Summary of all configuration settings captured for this Vault instance.

📂 Load Real Vault Data

This dashboard ships with sample data. To document a real environment, load a configuration JSON file with 📂 Load Data (top right). It accepts three formats: a Vault .cfg Global Settings export (File ▸ Export in the Vault client), this dashboard's own exported JSON, and raw Vault API output. When you load a .cfg, an ⬇ Export .cfg button appears — it preserves that original package and patches your lifecycle edits back in so it re-imports into Vault. You can also generate JSON by running the included Export-VaultConfig.ps1 PowerShell script against your ADMS/Vault server, then load the resulting file here. Your data is kept only in this browser (💾 Save / ↺ Reset) — nothing is uploaded.

Tip: the Replace toggle (next to Load Data) controls how a file is applied — when on, any section missing from the file is cleared so only the file's data remains (a clean full replace); when off it merges, keeping current data for sections the file doesn't contain.

Help & Docs
What this tool is, how to use it, and how it's distributed.

🚀 Quick Start

  1. Open it — this single HTML file runs in any modern browser, fully offline. It opens with sample data so you can click around safely.
  2. Load your config — use 📂 Load Data (top right). Three formats: a Vault .cfg Global Settings export (File ▸ Export in the Vault client — best option), this dashboard's own JSON, or PowerShell JSON from Export-VaultConfig.ps1.
  3. Replace toggle — Off (merge) keeps existing data for sections the file doesn't include (use this most of the time); On (replace) clears missing sections for a clean slate.
  4. Review & edit — use the left sidebar. Everything is editable inline. Lifecycles has a visual flowchart editor; Property Definitions expands per-property mappings.
  5. Save — 💾 Save keeps your work in this browser; ↺ Reset returns to sample data. Nothing is ever uploaded.
  6. Export / hand off — ⬇ Download JSON (re-loadable), ⬇ Export .cfg (appears after loading a .cfg; writes edits back so it re-imports into Vault), or 🖨 Print / PDF for a polished hand-off document.

📂 What the .cfg does & doesn't carry

The Global Settings .cfg carries: properties, lifecycles, categories, category rules, revision schemes/sequences, numbering schemes, and property mappings — these round-trip on import and .cfg export.

It does not carry users/groups, roles, security policy, folders, server/database, CAD, email, connectors, the Fusion Manage connector, backup, general settings, the revision table control, or lifecycle transition extras (custom job types, peer review, email notifications). Those are documented here and listed on the Manual Checklist for hand-application in Vault.

🔒 Data & Privacy

  • 100% client-side — data lives in this browser and in files you explicitly export. Nothing is uploaded; there is no backend.
  • Avoid putting secrets you don't want shared (e.g. service passwords) into a file you then commit or distribute. The email section intentionally omits password fields.

📦 Distribution & Version

  • The tool is the single file vault-config-dashboard.html — copy it anywhere; updates are a drop-in replacement.
  • The build stamp in the sidebar footer and on the PDF cover (e.g. ) identifies which copy you're running — quote it if you report an issue.

⬇ Export Vault .cfg — what this updates

Your edits are patched into the loaded Vault Global-Settings package. Everything not listed under "written" is preserved exactly as imported. Review before exporting:

✅ Written back to the .cfg
  • Lifecycles — states, colors, default, comments, transitions
  • Transition Actions / Criteria / Security
  • Revision schemes & sequences
  • Categories — lifecycle/revision assignment
  • Properties (UDP) — Active flag, new custom props
  • File Numbering scheme
  • Category Rules
  • Content-source Property Mappings
📄 NOT written (documentation only)
  • Users, Groups, Roles
  • Server/DB, Job Processor, Thin Client
  • Security policy (password, AD/LDAP)
  • CAD Integration page, Email, API, Backup, Audit
  • Fusion Manage connector (tenant, mappings, states)
  • Folder structure, General Settings, Notes
Less-obvious limits: Transition Custom Job Types & Peer Review are not written (no element in the export). Only File numbering is included (Item/Change-Order numbering live in Vault's base data); number prefixes/free-text fields aren't generated. Property mappings keep the exact moniker but not the friendly file-property name / classification. Roles & user accounts are server-level, never part of this .cfg.
🎯 The exported .cfg is stamped with the Build Number from Overview ▸ Vault Details (—). Set that to the target Vault's build number so it accepts the file; leave it as the source version to keep the original.
